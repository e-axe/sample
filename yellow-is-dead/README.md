# 舞台『イエローが死んだ』クライアント確認用LP

採用案：B / CAUTION WHITE。確認用サイトは `noindex,nofollow,noarchive`。

## 配置

GitHub `e-axe/sample` の `yellow-is-dead/`。既存のGitHub Pagesから配信する静的HTML/CSS/JavaScript一式。サーバー側Node.js、DB、APIは不要。

通常のWebサーバーでは `index.html`、`style.css`、`app.js`、`assets/`、`fonts/` を同じ階層関係で置く。ルート直下でもサブディレクトリでも動く相対パスを採用。

## 情報の更新

公開情報の正本はプロジェクトの「イエローが死んだ_公演情報最新版.md」。このリポジトリの `performance.json` は正本からの派生データ。情報変更は正本を先に更新し、JSONへ転記して次のコマンドを実行する。

```sh
python3 tools/build.py
```

初期HTMLに本文・氏名・料金・日程・リンクが含まれるため、閲覧時のJavaScriptやJSONの取得は必須ではない。日程・席種・CAST・販売状態・アクセス・クレジットをJSONで管理する。フォントはページに必要な文字のサブセットなので、氏名・文章追加時は字形の確認と必要に応じて再出力する。書体：Noto Sans JP（日本語、400/800）/ Anton（英数字）、SIL OFL。ライセンスはfonts内。

## 発売後の変更

販売開始を確認後、`sale.status` を `on_sale`、`sale.url` を正式URLへ更新する。`releaseText` も正式案内に更新してビルドする。日時経過による自動切替はしない。販売URLなしの場合、購入ボタンは出さずLP内のチケット情報を案内する。販売終了を確認した場合は `ended` と終了案内へ変更する。

販売日時・URLは正式情報を受領済み。発売前の主要CTAはLP内へ案内し、TICKET内は「カンフェティの販売ページを見る」と「出演日程を確認する」の2導線に整理。日程セクションの「料金・特典を見る」は販売状態にかかわらずLP内料金へ移動。`startsAt` / `endsAt` は日本時間のISO日時、表示文は正式案内の曜日・祝日表記を保持。

## Wキャスト出演回

正式に提示された4名の出演回のみ、固定人物IDの `appearances` / `appearanceLabel` に設定。各公演とCAST欄を同じデータから生成する。配役や他の出演者の出演回は推測しない。新規CASTの追加時も既存IDは維持する。

## CAST素材

初版は未受領の宣材写真を仮枠＋正式氏名で表示。人物画像は生成していない。写真は各 `cast-01`〜`cast-18` の人物に固定。掲載順とは別管理。

`performance.json` の該当人物の `image` に相対パスを、`focus` に焦点位置を設定して再ビルドする。推奨4:5、元1600×2000px、RGB/sRGB。対応表は `docs/materials.md`。写真受領後、全員の本人照合・トリミングを確認する。本番公開前に写真未受領の扱いを確定する。

## 2026-10-09 UIレビュー反映

ヘッダーは公演名を主表記。STORYは原文全文を初期表示し、段落・文ごとの間隔・動機カードで整理。レッド/ブルー/グリーン/ピンクは名前だけを各色にする。HEROは途中の新規案を採用せず、従来の採用画像・配置へ復帰。文字拡大に合わせたヘッダー高さとページ内移動後のフォーカスを調整。ページ内移動は即時スクロールとし、連続した移動/戻るによる位置ずれを防ぐ。

## 2026-10-09 追加レビュー

上部公演名は公式ロゴから採取した黄・赤・黒。冒頭のイエローだけ可読性を確保した金黄色。規制テープは左右まで連続し、必要情報を遮らない。CASTペアのグループ・氏名・出演回は維持し、カード間の装飾スラッシュを撤去。スマホメニューは画面高に応じて内部スクロールし、横向き・低い画面・文字拡大でも最後の項目へ到達できる。開閉と固定バーを即時同期し、Escape・項目選択・幅変更・Tab移動後の状態を安定させる。画像の読込が復旧した際はエラー表示を解除する。

販売ページ・地図・劇場公式案内など全外部リンクは新しいタブで開き、`noopener noreferrer` と読上げ用案内を付ける。発売後の全購入CTAにも同じ設定を適用。LP内移動は同じ画面。公演情報・採用HEROは維持。
